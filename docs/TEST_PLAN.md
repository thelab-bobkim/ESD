# TEST_PLAN — 테스트 계획

## 1. 테스트 범위
- 단위 테스트: 정책 엔진, 야간근무→전환 계산 로직, RBAC 가드
- API 통합 테스트: 주요 엔드포인트(출퇴근/상태변경/도착체크/야간근무/승인/정책)
- 시나리오(E2E) 테스트: PRD의 7개 시나리오
- 보안 테스트: 권한별 노출범위, 감사로그 기록 여부

## 2. 시나리오 기반 테스트 케이스

### TC-1. 고객사 상주자 출퇴근
1. 08:50 로그인 → 도착체크(resident/checkin) → `last_confirmed_at` 갱신 확인
2. 상태가 `RESIDENT_ONSITE`로 자동/수동 전환되는지 확인
3. 18:00 퇴근 처리 → `attendance_records.clock_out_at` 기록, 근무시간 계산 확인

### TC-2. 영업직 탄력근무
1. 월요일 출근 처리(HQ_WORKING)
2. 화~금 상태를 OFFSITE로 변경 → 위치 좌표 없이 상태값만 기록되는지 확인
3. 주간 근로시간 조회 시 정책의 코어타임 기준으로 집계되는지 확인

### TC-3. 엔지니어 야간근무
1. 주간 근무 종료(clock-out 이전 상태에서) 이후 22:00 야간근무 시작 등록
2. `night_work_sessions` 생성 확인(IN_PROGRESS)
3. 02:00 종료 등록 → workedMinutes=240 계산 확인

### TC-4. 야간근무 → 대체휴무 전환
1. TC-3 종료 후 `leave_conversion_requests` DRAFT 자동 생성 확인
2. 직원이 정식 신청(PENDING)으로 전환
3. 팀장 승인 → `leave_balances` 증가 확인, 감사로그 기록 확인

### TC-5. 초과근무 승인 누락 경고
1. 정책 `OVERTIME_APPROVAL_REQUIRED=true`, 초과근무 발생(예: 근무 12시간 초과)
2. 승인 없이 24시간 경과 시 `alerts`에 WARNING 레코드 생성 확인
3. A4 예외 알림 현황에 노출되는지 확인

### TC-6. 권한별 정보 제한
1. EMPLOYEE로 타인 상세조회 API 호출 → 403 확인
2. TEAM_LEAD로 타 부서 조회 → 403 확인, 자기 부서는 200
3. HR_ADMIN 조회 시 위치 상세 필드는 별도 권한 없으면 마스킹되는지 확인
4. 모든 관리자 조회에 감사로그(`VIEW`) 기록되는지 확인

### TC-7. 파일럿 그룹 운영 및 리포트
1. 파일럿 그룹 생성, 대상자 5명 추가
2. 대상자만 파일럿 전용 화면(P1~P3)에 데이터 노출 확인
3. 기간 종료 후 리포트 추출(CSV) 정상 동작 확인

## 3. 회귀 테스트 우선순위
1. 인증/권한(RBAC)
2. 상태변경/출퇴근 핵심 흐름
3. 야간근무-전환-승인 워크플로우
4. 정책값 변경이 즉시 반영되는지(캐시 무효화)
5. 감사로그 기록 누락 여부

## 4. 테스트 환경
- 로컬: `docker-compose.yml`로 backend+db 기동 후 `npm run test`(단위) / `npm run test:e2e`(API)
- 시드 데이터: `backend/prisma/seed.ts` (SAMPLE_ 접두어 계정 및 조직 데이터)

## 5. 완료 기준(Definition of Done, MVP)
- TC-1~TC-7 모두 통과
- 핵심 도메인(정책엔진, 전환계산) 단위 테스트 커버리지 확보
- 감사로그 누락 케이스 0건

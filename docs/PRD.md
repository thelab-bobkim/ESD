# PRD — 전직원 상황판 및 근로시간 통합관리 시스템

버전: v0.1 (파일럿용 MVP)
작성일: 2026-07-30

## 1. 배경

- 회사 규모: 총 150명
  - 본사 근무자 80명
    - 영업 20명, 엔지니어 50명 → 월요일 본사 출근 후 화~금 탄력근무
    - 기타 본사 인력 10명 (일반 고정근무로 가정, `CONFIGURABLE_WORK_TYPE`으로 조정 가능)
  - 고객사 상주 근무자 70명 → 기본 09:00~18:00 근무 (`CONFIGURABLE_RESIDENT_WORK_HOURS`)
- HR은 다음 제도를 별도로 정비 중이며, 시스템 출시 이후에도 계속 바뀔 수 있음:
  - 탄력근무 제도, 보상휴가/대체휴무 규정, 취업규칙/서면합의/동의서
  - → **시스템은 제도 문구·규칙을 하드코딩하지 않고 "정책값"으로 관리자가 설정**한다. (원칙, `core_principles` 참조)

## 2. 목표 (Business Goals)

1. 전직원의 현재 근무상태를 상황판으로 한눈에 확인
2. 고객사 상주 인력의 현재 근무지 상태 확인
3. 본사 영업/엔지니어의 실근로시간 관리
4. 엔지니어 야간근무 발생 시 익일 대체휴무/보상휴가 전환 프로세스 처리
5. 파일럿 운영 후 전사 확산 가능한 구조 확보

## 3. 비목표 (Out of Scope for MVP)

- 실시간 GPS 이동경로 저장/지도 추적 (기본 비활성화, 향후 정책 스위치로만 확장 가능하게 설계)
- 급여 자동 정산/이체 연동 (리포트 추출까지만; 실제 정산 시스템 연동은 차기 과제)
- 다우오피스 등 외부 그룹웨어와의 실시간 양방향 연동 (파일럿 단계는 독립 시스템으로 운영, 계정은 CSV/수동 등록)
- 모바일 네이티브 앱 (반응형 웹으로 모바일 대응)

## 4. 핵심 설계 원칙 (Core Principles)

| 원칙 | 설명 |
|---|---|
| 근무상태/근로시간 관리 시스템 | 상시 동선 추적 시스템이 아님 |
| 위치정보 최소수집 | 좌표 상세 추적이 아니라 "도착 여부/현재 상태/마지막 확인 시각" 중심 |
| GPS 이동경로 기본 비활성화 | `CONFIGURABLE_ENABLE_GPS_TRACKING = false` 기본값 |
| 정책값 분리 | 법률/제도 문구·기준시간·전환비율 등은 `policy_settings` 테이블에서 관리 |
| 권한기반 접근통제 | RBAC, 위치정보 상세조회는 별도 권한 |
| 감사로그 필수 | 상태변경/승인/정정/관리자 조회 이력 전부 기록 |

## 5. 이해관계자 및 역할 (Roles)

| 역할 | 설명 |
|---|---|
| EMPLOYEE | 일반 직원 (본사/고객사 상주 공통) |
| TEAM_LEAD | 팀/부서 리더 — 소속 팀원만 조회 및 1차 승인 |
| HR_ADMIN | 인사 담당자 — 정책설정, 리포트, 전사 조회 |
| SYSTEM_ADMIN | 시스템 관리자 — 계정/권한/파일럿 대상 관리, 감사로그 조회 |
| PILOT_MANAGER | 파일럿 운영 담당 (HR_ADMIN과 겸직 가능) — 파일럿 그룹/기간/리포트 |

한 사용자는 여러 역할을 가질 수 있다 (`user_roles` N:M).

## 6. 사용자 시나리오 (Scenario Requirements) → 요구사항 매핑

| # | 시나리오 | 관련 기능 |
|---|---|---|
| 1 | 고객사 상주자 09시 이전 도착체크 → 18시 퇴근 | 도착체크, 출근/퇴근, 상태=RESIDENT_ONSITE |
| 2 | 영업직 월요일 본사출근, 화~금 외근 | 상태 변경(OFFSITE), 탄력근무 정책 적용 |
| 3 | 엔지니어 주간근무 후 야간작업 | 야간근무 시작/종료 등록 |
| 4 | 22:00~익일 02:00 야간작업 → 대체휴무 전환 | 야간근무 등록 → 전환규칙 적용 → 대체휴무 신청/승인 |
| 5 | 초과근무 승인 누락 경고 | 예외 알림(미승인 초과근무) |
| 6 | 관리자 권한별 정보 제한 노출 | RBAC + 필드 단위 마스킹 |
| 7 | 파일럿 그룹만 우선 운영 후 리포트 추출 | 파일럿 대상 그룹, 파일럿 전용 리포트 |

각 시나리오의 상세 흐름은 `TEST_PLAN.md`의 시나리오 테스트 케이스에서 재사용한다.

## 7. 기능 범위 (Scope) 요약

`system_scope`의 A(직원)/B(관리자)/C(인사·운영)/D(파일럿) 4개 카테고리를 그대로 채택하며, 상세 화면·API는 `SCREENS.md`, `API_SPEC.md` 참조.

## 8. 정책값 목록 (초기 관리자 설정 항목 — MVP 기본값 포함)

정책은 전부 `policy_settings` 테이블의 key-value(+타입)로 관리하며, 아래는 **초기 시드 값**(운영 중 관리자가 변경 가능):

| 정책 키 | 설명 | 초기값 |
|---|---|---|
| `FLEX_WORK_ENABLED_GROUPS` | 탄력근무 적용 대상 그룹 | 영업, 엔지니어 |
| `FLEX_WORK_CORE_HOURS` | 탄력근무 코어타임 | `CONFIGURABLE_10:00-16:00` |
| `RESIDENT_STANDARD_HOURS` | 고객사 상주 표준 근무시간 | `09:00-18:00` |
| `NIGHT_WORK_START` / `NIGHT_WORK_END` | 야간근무 판정 시간대 | `22:00` / `06:00` |
| `NIGHT_WORK_COMPENSATION_TYPE` | 야간근무 보상방식 | `CONFIGURABLE_대체휴무` (대체휴무/보상휴가/수당 중 선택) |
| `NIGHT_TO_LEAVE_CONVERSION_RATE` | 야간근무시간→휴가 전환 비율 | `CONFIGURABLE_1:1` |
| `OVERTIME_APPROVAL_REQUIRED` | 초과근무 승인 필수 여부 | `true` |
| `OVERTIME_WARNING_THRESHOLD_HOURS` | 장시간근무 경고 기준(일) | `CONFIGURABLE_12시간` |
| `BREAK_MINIMUM_MINUTES` | 근무 N시간당 최소 휴게시간 | `CONFIGURABLE_4시간당 30분` |
| `UNCONFIRMED_STATUS_ALERT_MINUTES` | 상태 미확인 경고 기준 | `CONFIGURABLE_120분` |
| `DATA_RETENTION_MONTHS` | 근태/위치 로그 보관기간 | `CONFIGURABLE_36개월` |
| `ENABLE_GPS_TRACKING` | 실시간 GPS 추적 여부 | `false` (기본 비활성화) |

## 9. 성공 기준 (MVP)

- 파일럿 그룹(예: 영업팀 일부 + 엔지니어 일부 + 고객사 상주자 일부) 기준으로 실제 운영 가능
- 직원/관리자/인사 화면 분리
- 상황판–근로시간–야간근무–대체휴무 워크플로우가 실제로 연결되어 동작
- 정책값이 하드코딩 없이 관리자 화면에서 변경 가능
- README만으로 로컬/파일럿 서버 실행 가능

# PILOT_PLAN — 파일럿 운영 계획

## 1. 목적
전사 확산 전, 소규모 대표 그룹으로 시스템을 실제 운영하며 정책값/UX/알림 기준을 검증한다.

## 2. 파일럿 대상 그룹 (예시 — 실제 인원은 `pilot_groups` 화면에서 지정)

| 그룹 | 인원(예시) | 목적 |
|---|---|---|
| 영업 일부 | `SAMPLE_5명` | 탄력근무 + 외근 위주 시나리오 검증 |
| 엔지니어 일부 | `SAMPLE_8명` | 야간근무 → 대체휴무 전환 워크플로우 검증 |
| 고객사 상주 일부 | `SAMPLE_5명` | 도착체크/표준시간 근무 시나리오 검증 |
| 관리자/HR | `SAMPLE_3명` | 상황판, 승인, 정책설정, 리포트 검증 |

## 3. 기간 (예시)
- 준비: `CONFIGURABLE_1주` (계정/조직 데이터 세팅, 교육)
- 파일럿 운영: `CONFIGURABLE_4주`
- 결과 분석 및 정책 조정: `CONFIGURABLE_1주`

## 4. 단계별 계획

### Phase 0. 준비
- 파일럿 대상자 계정 생성, 부서/고객사 매핑
- 정책 초기값 확정(코어타임, 야간근무 판정시간, 전환비율 등) — HR 제도 확정 전이므로 **잠정값**으로 설정하고 언제든 변경 가능함을 공지
- 사용법 안내(직원용 1페이지 가이드)

### Phase 1. 운영 1~2주차
- 매일 상황판/알림 모니터링
- 주 1회 파일럿 피드백 수렴(P2 화면 + 별도 인터뷰)
- 이슈 발생 시 정책값 우선 조정, 코드 변경은 최소화

### Phase 2. 운영 3~4주차
- 알림 임계값(장시간근무, 미확인 등) 튜닝
- 대체휴무 전환/승인 워크플로우 실사용 검증
- 관리자 권한별 노출 정보 재검토

### Phase 3. 결과 분석
- 참여율, 알림 발생 빈도/유형, 승인 소요시간, 피드백 카테고리별 집계
- HR 제도 확정에 참고할 실측 데이터 제공(예: 실제 야간근무 발생 빈도/시간대)
- 전사 확산 여부 및 우선 개선 항목 결정

## 5. 리스크 및 대응
| 리스크 | 대응 |
|---|---|
| HR 제도 미확정으로 정책값 잦은 변경 | 정책값 분리 설계로 코드 변경 없이 대응 |
| 직원의 상태변경 누락 | 미확인 알림 + 간단한 UX(원탭 상태변경) |
| 개인정보/위치정보 우려 | 좌표 수집 없음을 명시, 정책 문서에 최소수집 원칙 공지 |
| 파일럿 참여자 피로도 | 참여 그룹 소규모 유지, 피드백 채널 상시 개방 |

## 6. 파일럿 종료 기준(Go/No-Go)
- 핵심 워크플로우(출퇴근/상태변경/도착체크/야간근무→전환→승인) 오류 없이 동작
- 감사로그 누락 없음
- 파일럿 참여자 만족도/피드백이 확산 가능 수준
